# 2.5.0

The owner's plan, to be written up when it ships: a sandbox for every
contributor, and one shared scope in the open. Settled on 2026-09-22, with
[2.4.0](2.4.0.md), which it builds on. The MCP outline moved on to
[2.6.0](2.6.0.md).

- Every contributor has a sandbox of their own. The versions they save are theirs, and nobody else sees them — not a publisher, not the administrator. Users & access shows how many versions a person holds, not what.
- **Share** puts a fixed copy of a sandbox version among the **Shared** versions, which contributors and above can open. Sharing again under the same name writes over your own share; a name someone else holds is refused, with their name in the message; the published one is refused.
- **Take a copy** brings a shared version into your sandbox to work on.
- **Publish** goes live from Shared only. A publisher shares their own version and then publishes it: two clicks, and one place to look for what is live.
- A shared version is not edited in place. Whoever shared it, a publisher or the administrator can rename or delete it; the published one cannot go.
- At the upgrade every version already in the database becomes shared. Sandboxes start empty and fill as people take copies.
- A viewer's world does not change: the published map, and nothing else.
- Storage: a version gains whose sandbox it is in (none for Shared), a name unique per sandbox and once for Shared, and `v1`, `v2`… counted per sandbox. `?version=` stays for a shared version; a sandbox version is `?draft=`, which only its owner can open.
- Words: Share, Shared, Take a copy, Publish. The Versions dialog has two lists: **My sandbox** and **Shared**.
