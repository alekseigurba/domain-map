# 2.9.0

A name box used to offer only the people who had already opened the map. The
people list is made at a first sign-in, so a product manager who had never
signed in could not be picked as the owner of a domain or the lead of a
capability — their name had to be typed out in full, and was typed out a
little differently each time. This release has the name boxes ask the
organisation's directory as well: two letters typed bring up anyone in Entra
ID whose name or address matches.

The map reached by an agent from outside has moved on once more: its outline
is on [2.10.0](2.10.0.md).

## Breaking changes

None. No map-file change, no migration, and no route taken away.

| What | Was | Is |
| --- | --- | --- |
| `GET /api/people/directory?q=` | not there | a contributor's: anyone in the directory matching `q`, as `{ enabled, people, error }` |
| `AUTH_DIRECTORY` | not there | `false` turns the look-up off; it is on wherever Microsoft sign-in is set up |
| `createDomainMapServer({ directory })` | not there | a `{ search(query) }` of your own, for a directory that is not Entra ID |

## Upgrading

Nothing to run in the app. In Entra ID, the app registration the map signs in
with needs one more permission before the look-up finds anyone:

1. **API permissions** → **Add a permission** → **Microsoft Graph** →
   **Application permissions** — not Delegated.
2. **User.ReadBasic.All**, then **Add permissions**.
3. **Grant admin consent** for the tenant.

The server uses the client id and secret it already signs in with, so no new
variable is needed in a deployment. Until the permission is granted, the
server's log says so once — *Could not look people up in Microsoft Graph …
Grant the app the application permission User.ReadBasic.All* — and the name
boxes offer the people list as they did before. Nothing else is affected.

A server with sign-in off and no Entra ID settings has no directory, and
answers every look-up with nobody.

## How it works

### The boxes

- **Every box that names a person asks**: an area's, a domain's or a
  capability's **Owner**, a person's **Name**, and a cell of the **Roles**
  grid. Each still offers, first, the names it always did — the people list,
  and in the grid the people already on the map — and then the directory's.
- It asks **once two letters are in and the typing has paused** for a quarter
  of a second. One letter matches half the organisation; the pause keeps a
  name typed quickly from asking at every letter.
- **Each word is matched on its own**, against the name and both addresses,
  so *jenny atm* finds *Atmer, Jenny* whichever way round the directory writes
  it. Fifteen names at most: a list to pick from, not to read.
- **Someone already on the people list is offered once**, told apart by their
  address.
- **A name picked is a name**, as a typed one is. It gives that person
  nothing, and puts nobody on Users & access; they arrive there by signing in,
  as before. An Owner picked from the directory carries no link to a person
  until there is one on the list to link to.

### The server

- The look-up is the server's, not the page's. It asks Microsoft Graph **as
  the application**, with the client id and secret that sign-in already uses,
  for the users matching what was typed — never as the person typing, who
  would otherwise have to consent to it.
- `User.ReadBasic.All` reads a user's **name and addresses, and nothing
  else**. That is why the look-up is of the **whole tenant**: the permission
  cannot read who is assigned to the Enterprise application, nor who is in a
  group, so it cannot narrow the names to the people who may sign in.
- An answer is kept for **five minutes**, so a box typed into and back does
  not ask twice. A refusal is warned about once for as long as it says the
  same thing, and Graph is left alone for five minutes after it, so a missing
  permission is not asked about at every letter.
- **Whoever may see the people list may look**: contributors and above. A
  viewer is not shown the list, and is not shown this.

## What it does not do

- **Only the people who may sign in.** That needs `Application.Read.All` and
  `GroupMember.Read.All` as well, to read the app's assignments and the
  members of its groups.
- **No guests or disabled accounts left out.** `User.ReadBasic.All` cannot see
  whether an account is enabled, and a guest is a user like any other.
- **Not in Users & access.** Adding someone there is still a name, an address
  and a role, typed in.
- **No other directory.** A provider other than Entra ID brings its own, as
  `createDomainMapServer({ directory })`.

## Known issues

- Graph's search runs on an index that is kept up to date eventually, not at
  once: someone added to the tenant a few minutes ago may not be found yet.
